## Method

- The spike keyboard is a 4 by 3 grid of probe keys, each one call on `textDocumentProxy`.
- Every key logs `documentContextBeforeInput`, `documentContextAfterInput`, `selectedText`, `hasText`, and `documentIdentifier` as code points, before and after the call.
- `MARK1` is U+AC00, `MARK2` is U+AC01, `MARK3` is U+AC00 U+AE30, `MARKJ` is U+3131, `MARKA` is U+1100 U+119E, `INSERT` is U+0078, `SPACE` is U+0020.
- Step list per host, in order, `CLEAR`, `MARK1`, `MARK2`, `MARK3`, `MARK1`, `UNMARK`, `INSERT`, `MARK1`, `DELETE`, `UNMARK`, `SPACE`, `MARKJ`, `MARKA`, `UNMARK`, `DUMP`.
- An XCUITest walks the step list and asks the Mac for a screenshot after every step. Screenshot names are `<host>-<field>-<step index>-<step>.png`.
- The keyboard was enabled through an XCUITest against `com.apple.Preferences`, screenshots `enable-00-settings.png` through `enable-06-after.png`. The Settings row carries identifier `sh.cho.spike-s2` and label `SpikeHost` under Third-Party Keyboards.
- Enablement verified out of band with `xcrun simctl spawn 1ED851F4-6C4E-43CD-A28D-480FD91B4240 defaults read .GlobalPreferences AppleKeyboards`, which returned `en_US@sw=QWERTY;hw=Automatic`, `emoji@sw=Emoji`, `sh.cho.spike-s2.keyboard`.
- Logs read back with `xcrun simctl spawn 1ED851F4-6C4E-43CD-A28D-480FD91B4240 log stream --level info --predicate 'subsystem == "spike.s2"' --style compact`. A stream without `--level info` drops every `Logger.info` line and looks empty.

## `documentContextBeforeInput` while text is marked

This is the finding node K2 depends on. It held in every host that loaded the extension.

- The marked text is not part of `documentContextBeforeInput`. Committed text before the marked region is.
- On an empty field with U+AC00 marked, the property is `nil`, not the empty string.
- With U+AC00 U+0078 committed and U+AC00 marked on top, the property is exactly U+AC00, U+0078.
- `hasText` is true while text is only marked, so `hasText` and `documentContextBeforeInput` disagree during a composition.
- After `unmarkText()` the property gains exactly the marked code points and nothing else.
- Marking again after a commit never duplicates the committed text.

## `deleteBackward()` against a marked string

A separate probe marks U+AC00 U+AE30 and calls `deleteBackward()` once.

- One call removes the whole marked string, not its last code point. `deleteprobe-01-MARK3.png` shows two syllables under the composing underline and `deleteprobe-02-DELETE.png` shows the empty field with its placeholder.
- The value read back inside the same call is stale. `documentContextBeforeInput` reported U+AC00 immediately after the call and `nil` with `hasText=0` at the next key, which is the state the screenshot shows.

```
S2|step=MARK3|phase=after|before=NIL|after=NIL|selected=NIL|lang=NIL|hasText=1
S2|step=DELETE|phase=before|before=NIL|after=NIL|selected=NIL|lang=NIL|hasText=1
S2|step=DELETE|phase=after|before=U+AC00|after=NIL|selected=NIL|lang=NIL|hasText=1
S2|step=DUMP|phase=before|before=NIL|after=NIL|selected=NIL|lang=NIL|hasText=0
```

## Hosts not present in the runtime

- `com.apple.mobilenotes` and `com.apple.mobilemail` are not installed in the iOS 27.0 simulator runtime. `xcrun simctl listapps` lists neither.
- XCUITest reports `Failed to launch com.apple.mobilenotes: Application info provider (FBSApplicationLibrary) returned nil for "com.apple.mobilenotes"`, and the same string for `com.apple.mobilemail`.
- Reminders stands in for a system app editable body, Contacts search and Messages search stand in for `UISearchBar` in a system app.
- Notes body and Mail compose body move to node Q2 on a physical device.

## Other observations

- `documentInputMode?.primaryLanguage` is `nil` in most hosts and `ko-KR` in the Messages compose field and the Reminders title field. K2 must treat it as optional and never branch on it.
- `documentContextAfterInput` is `nil` in every step of every host.
- `selectedText` is `nil` throughout, including while text is marked.
- `hasFullAccess` is false and `needsInputModeSwitchKey` is false on this device, logged as `S2|event=APPEAR|fullAccess=0|needsSwitch=0`. The system draws the globe below the keyboard view, so a keyboard-drawn globe key is redundant on this form factor.
- A marked U+1100 U+119E renders and commits as the two separate code points. No host recomposed it, so the v1.1 pending-araea rendering survives a marked-text round trip.
- No host showed a QuickType candidate row while the spike keyboard was up. The tree dump of a focused field carries only the extension's own buttons.
- Forty `deleteBackward()` calls in a row dismiss the Reminders new-reminder row, so a host can tear down the editing session under bulk deletes.
- XCUITest exposes a third-party keyboard's buttons as descendants of the host application element under the view's own accessibility identifier. There is no `Keyboard` container element for it, unlike the system keyboard.

## What K2 should build

- Use `setMarkedText(_:selectedRange:)` for the composing syllable and `unmarkText()` to commit, with no fallback path. Every host that loads the extension passed.
- Do not add a fallback for the two password fields. The extension never loads there, so there is no code path to fall back to.
- Never derive composition state from `documentContextBeforeInput`. It omits the marked text and can be stale immediately after a mutation. The engine's `Composition` is the only source of truth.
- Never call `deleteBackward()` while text is marked. Rewind in the engine and re-mark instead, since one call clears the whole marked string.
- Treat `documentContextBeforeInput` as committed text only, which is exactly what K5 needs for the `UITextChecker` prefix.
