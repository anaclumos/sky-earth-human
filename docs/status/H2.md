## Swift 6 concurrency note

`MailComposeView.Coordinator` must be `@MainActor` to call the SwiftUI `dismiss` environment action from its `MFMailComposeViewControllerDelegate` callback. `MFMailComposeViewControllerDelegate` is an unaudited Objective-C protocol (confirmed against `MessageUI.apinotes` in the iOS 27 simulator SDK, no concurrency annotations present), so an `@MainActor` type conforming to it as written fails with a `ConformanceIsolation` build error: "Conformance of 'MailComposeView.Coordinator' to protocol 'MFMailComposeViewControllerDelegate' crosses into main actor-isolated code and can cause data races." The fix is an explicit `@preconcurrency` on the conformance: `NSObject, @preconcurrency MFMailComposeViewControllerDelegate`.

Checked before use, not from memory:
- `UIApplication.openSettingsURLString`: present, not deprecated, per `UIKit.apinotes` in the iOS 27 simulator SDK.
- `ShareLink(item:message:label:)` and `ShareLink(item:message:)`: present in the SwiftUI 27 simulator swiftinterface, matches v1.1's call shape.
- `EnvironmentValues.requestReview` / `RequestReviewAction`: present in `_StoreKit_SwiftUI`'s swiftinterface, `@available(iOS 16.0, ...)`, not deprecated. `SKStoreReviewController.requestReview(in:)` (the class method v1.1 does not use) is deprecated in favor of `AppStore.requestReview(in:)`; the environment action is the non-deprecated route and is what v1.1 already used.
- `MFMailComposeViewController` and `MFMailComposeViewControllerDelegate`: present, no deprecation annotations in the header or apinotes.
