## Height formula

Read from `keyboard/Views/KeyboardView.swift` at the commit above: `VStack(spacing: 8)` of 4 rows, `.padding(.horizontal, 10)`, `.padding(.bottom, 10)`. No top padding. So:

```
gridHeight = 4 * rowHeight + 3 * 8 + 10
```

Row heights are the assigned values: small 48, medium 56, large 64. Medium matches the v1.1 fixed key height (`docs/status/K1.md`: "Key height | 56.0 points, fixed by `minHeight: 56`").

When `predictionBarShown` is true, `HeightMetrics` adds `HeightMetrics.predictionBarHeight` (60 points) on top of `gridHeight`.

## Prediction bar number

Read with `git show archive/v1:keyboard/KeyboardView.swift`. The autocomplete row is:

```swift
HStack { ... }
  .frame(height: 50, alignment: .center)
  .background(Color("KeyboardBackground"))
  .padding(5)
```

`.frame(height: 50)` sets the row's own height, then `.padding(5)` adds 5 points on every side, so the total vertical footprint that row occupies in v1.1's `VStack(spacing: 0)` is 50 + 5 + 5 = 60 points. `HeightMetrics.predictionBarHeight` is 60, not 50, because 60 is the actual space the strip consumes in the layout, not just its inner frame. This is a `static let` on `HeightMetrics`, not a local inside `inputViewHeight`, specifically so K6's prediction bar view can read the same number instead of repeating it. This value is not separately measured in the harness below: K6 has not built the 2.0 prediction bar yet, so there is nothing to show it against. The harness always calls `apply(keySize:predictionBarShown: false)`.

Computed (not measured) heights with the prediction bar shown: small 226 + 60 = 286, medium 258 + 60 = 318, large 290 + 60 = 350.

## HeightController

`@MainActor final class` holding a `UIView` reference and one optional `NSLayoutConstraint`. `apply(keySize:predictionBarShown:)` creates the constraint on first call (priority 999, `isActive = true` once) and only mutates `.constant` on every later call, matching what `docs/spikes/S3.md` measured to work: "Activating with `isActive = true` on first creation and only touching `.constant` afterward ... is what kept the updates snapping cleanly." No `UIView.animate` wrapper, so the height snaps per the task requirement. `apply` calls `view.setNeedsLayout()` and `view.layoutIfNeeded()` synchronously after setting the constant, the same pattern S3's `applyHeight()` used.

Per S3, the system adds its own fixed chrome outside the extension's view (92pt iPhone portrait, 34pt iPhone landscape, 75pt iPad both orientations). `HeightController`'s constant is the height of the extension's own view only; it does not add or subtract that offset.

## What I1 must wire

- `KeyboardViewController.swift` creates one `HeightController(view: view)` and keeps it for the extension's lifetime. Do not create a second height constraint anywhere else on that view.
- Call `heightController.apply(keySize:predictionBarShown:)` once during initial setup with the `KeySize` read from `SettingsReader` (via `KeyboardModel`, which already stores `keySize` from `settings.keySize`).
- Call `apply` again every time `KeyboardModel.keySize` changes, which happens inside `KeyboardModel.reloadSettings()`. `KeyboardView.onAppear` already calls `reloadSettings()`; I1's controller should call it again on foreground, per `docs/status/K1.md`.
- `predictionBarShown` should reflect whatever K6's prediction bar view actually renders on screen, not just `KeyboardModel.isPredictionEnabled` in isolation, since the bar may still be conditionally hidden by K6's own merge rules. Confirm the exact visibility condition against K6's implementation once it lands, and call `apply` again whenever that visibility flips.
- Do not add any compensation for the system's own chrome outside the extension's view (92 / 34 / 75 points per `docs/spikes/S3.md`). `HeightController`'s constant is only the height of this extension's own view.
- The height change must stay unanimated: do not wrap the `apply` call or anything downstream of it in `UIView.animate`.
- `HeightMetrics.inputViewHeight` already accounts for the prediction bar's own height when `predictionBarShown` is true, so I1 must not add `HeightMetrics.predictionBarHeight` again on top of what `apply` already sets.
