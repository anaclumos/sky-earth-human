### M1, the new completion hook

```swift
public func canExtend(to text: String) -> Bool
```

- True when idle.
- Otherwise true when some run of presses, the empty run included, any of the ten keys, each press inside or outside the cycle lock, leaves a rendering that is a non-empty prefix of `text`.
- Every current block is accounted for by construction. The rendering compared is the whole composition, and no press removes a block except a lone consonant folding into the syllable before it.
- The prefix is compared on Unicode scalars, the form the engine renders. `text` must be precomposed, which is what the engine itself emits.
- `Automaton.reach`, the full closure, is removed.

How the search is directed.

- Rendering is one to one, so `text` is parsed into the blocks it would render from, and a state is accepted when its blocks are a prefix of those.
- Blocks before the last two never change, so they must already match. That is checked once.
- The search runs on the last two blocks plus the one block that may follow. A state is kept only while `viable` holds.
  - The block before the last keeps its initial and vowel. It changes only when the last block is a lone consonant that folds into it.
  - A block keeps its initial once it has a vowel. A vowel only moves along the automaton, and not at all once a final sits behind it.
  - A final must be able to settle as the wanted one by cycling on its key, by growing into a compound, by a fold, or by leaving as the next initial on the same key.
- The target is cut at one block past the current count. If any accepting state exists, one exists within that bound, because a block past it is only ever created behind a block that already rendered its part of the text.
- Every rule in `viable` errs toward keeping a state, so a wrong rule can only cost time or lose an answer. Losing an answer is what the brute force checks.

Independent brute force.

- `scratchpad/e3v2/oracle/extend_ref.py` searches whole block lists with `press_vowel` and `press_consonant` from the oracle, cycling and not. It assumes no bound on the number of blocks.
- It drops a state only on four facts that the verifier's table check confirms on all 7,426,320 transitions. Blocks before the last two never change. A rendering shrinks by at most one scalar later. The block before the last keeps its initial and vowel. A last block with a vowel keeps its initial and its place.
- A second exhaustive search in Swift follows the same four rules and shares only `Automaton.press` with the engine.
- Pairs come from states within four or five presses of empty. Texts are renderings reached by random walks from the state, the same with a syllable or U+0021 appended, with the last scalar cut, with one scalar replaced, and random syllable strings.

### m2, history

- The composer keeps the live block list once. A history entry holds the key, the instant, the count of leading blocks the press left alone, and the at most two blocks it overwrote.
- A press reads and writes the last two blocks only. Backspace cuts the list back to the saved count and appends the saved blocks, which restores the previous state exactly, including the lock instant of the press it returns to.

Resident size after N presses with no commit, verifier's `perf` mode, release build.

| Presses | Before | After |
| --- | --- | --- |
| 1,000 | 11 MiB | 6 MiB |
| 5,000 | 141 MiB | 8 MiB |
| 20,000 | 1,985 MiB | 12 MiB |

- One press still costs time linear in the composition, 98 us at 20,000 presses, because `press` returns the full rendering as the contract requires. That was 102 us before and is unchanged by design.
